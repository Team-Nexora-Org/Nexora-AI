    38→1. PROBLEM CONTEXT
    39→
    40→Real infrastructure projects already have structured project schedules in systems such as Primavera P6, Microsoft Project, or other PMIS platforms.
    41→
    42→The project schedule contains planned L5/L6 activities.
    43→
    44→However, actual execution information is distributed across multiple supervisors and disciplines.
    45→
    46→Examples:
    47→
    48→* Piping supervisor
    49→* Civil supervisor
    50→* Mechanical supervisor
    51→* Electrical supervisor
    52→* Instrumentation supervisor
    53→
    54→They may report through:
    55→
    56→* Voice
    57→* Text
    58→* Daily progress reports
    59→* Excel
    60→* Site diaries
    61→* PDFs
    62→* Photos
    63→
    64→The terminology used by the field does not necessarily match the terminology used by the schedule.
    65→
    66→Example:
    67→
    68→Schedule:
    69→
    70→“A10931 — Erect Spool Line 24-XX”
    71→
    72→Field:
    73→
    74→“Line 24-XX ka spool erection complete hai.”
    75→
    76→Another:
    77→
    78→“24-XX spool fixed and erection finished.”
    79→
    80→Another:
    81→
    82→“Piping team completed erection of the 24-XX spool.”
    83→
    84→These statements can represent the same planned activity.
    85→
    86→The problem is therefore not merely data entry.
    87→
    88→The core problem is:
    89→
    90→HETEROGENEOUS FIELD EXECUTION DATA MUST BE INTERPRETED AND RECONCILED AGAINST STRUCTURED L5/L6 PROJECT SCHEDULE ACTIVITIES.
    91→
    92→The planner should not have to manually read every report, determine what happened, find the corresponding schedule activity, calculate progress, and update the schedule from scratch.
    93→
    94→NEXORA is the intelligent reconciliation layer between field execution and the existing project schedule.
